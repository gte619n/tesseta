1. **ADC / auth** as an identity with (at minimum): `roles/datastore.owner` (or
   Firestore admin) for the DB + backup schedule + delete-protection changes,
   `roles/storage.admin` for the bucket versioning imports, `roles/monitoring.editor`
   and `roles/logging.configWriter` for the monitoring resources.
   ```bash
   gcloud auth application-default login
   gcloud config set project health-fitness-160
   ```
2. **Remote state bucket** already exists (`health-fitness-160-tf-state`, see
   `README.md`). `tofu init` uses it.
3. **Billing budget only:** supply `var.billing_account_id` AND grant the
   applying identity `roles/billing.costsManager` on that billing account
   (id from the audit: `0008AE-458280-6056E2`). If you leave
   `billing_account_id` empty (the default), the budget resource is skipped
   (`count = 0`) and everything else still applies.
4. **APIs** must be enabled: `firestore.googleapis.com`, `monitoring.googleapis.com`,
   `logging.googleapis.com`, and (for the budget) `billingbudgets.googleapis.com`.
   Error Reporting (OBS-001 free win) is a one-liner:
   ```bash
   gcloud services enable clouderrorreporting.googleapis.com billingbudgets.googleapis.com --project=health-fitness-160
   ```

### Belt-and-suspenders: out-of-band gcloud (optional, if you prefer not to import)

DATA-001 PITR + delete-protection can be enabled immediately without Terraform;
the subsequent `tofu plan` then shows those two fields as already-correct no-ops.

```bash
# PITR + delete-protection on production (DATA-001).
gcloud firestore databases update --database=production \
  --enable-pitr --enable-delete-protection --project=health-fitness-160

# Backup schedules (DATA-001) — equivalent to the two terraform schedules.
gcloud firestore backups schedules create --database=production \
  --recurrence=daily --retention=7d --project=health-fitness-160
gcloud firestore backups schedules create --database=production \
  --recurrence=weekly --day-of-week=SUN --retention=14w --project=health-fitness-160

# DATA-002 TTL on the correct database.
gcloud firestore fields ttls update expiresAt \
  --collection-group=idempotencyKeys --enable-ttl \
  --database=production --project=health-fitness-160

# GCS versioning + noncurrent lifecycle (DATA-001) for each app bucket.
for b in nutrition-photos food studio equipment gym-photos exercise-media \
         android-releases exports firestore-exports; do
  gcloud storage buckets update "gs://health-fitness-160-$b" --versioning \
    --project=health-fitness-160
done

#   {"rule":[{"action":{"type":"Delete"},

```

## Notes / caveats

- **Restore goes to a NEW database.** A Firestore backup/PITR restore writes to a
  brand-new database; you then repoint `app.persistence` database name (or
  re-import). Backups do **not** carry TTL policies, security rules, or composite
  indexes — re-apply `firestore_ttl.tf` + `infra/scripts/deploy-firestore-indexes.sh`
  against the restored DB. (A full restore runbook — DATA-001's `docs/runbooks/`
  deliverable — is out of scope for this infra-only change.)
- **Budgets alert, they do not stop spend.** Pair with the SEC-001 rate limiter
  (out of scope here).
- SEC-012 (bucket public-read privacy) is intentionally left alone; the bucket
  resources here manage only versioning + lifecycle and `ignore_changes` the rest.
