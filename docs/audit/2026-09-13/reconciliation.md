## 2. Systemic patterns

### Pattern A — "Silent failure is the default failure mode" — **ACCEPTED**

**Root cause:** the codebase's house idiom is graceful degradation without a signal. Offline-first design legitimately hides *offline*, and that habit metastasized: error paths swallow (`runCatching{}.getOrNull()`, `.catch(() => null)`, `|| true`, early `return` on empty), safety nets (periodic sync floor, refresh sweeps, self-heal sweeps, tolerant readers) paper over dead subsystems just well enough to hide them, and there is no telemetry substrate (OBS-001/002/003) to make any of it visible. Every one of the four motivating prod incidents (weeks of dead deploys, dead FCM, Cloud Tasks 401 loop, webhook-as-probe drops) is an instance, and most of the underlying silent paths are **still silent today**.

**Members (24):** OBS-001, OBS-002, OBS-003, OBS-004, OBS-005, OBS-006, OBS-008, OBS-009, DATA-007, DATA-008, DATA-010 *(hard-parse poisons range reads / tolerant readers drop)*, ARCH-003, ARCH-004 *(silent UTC fallback)*, UX-003, UX-005, UX-011, CICD-001, CICD-003 *(`|| echo 0` fallback)*, CICD-005, CICD-007/SUP-008 *(`--no-frozen-lockfile` silent degrade)*, DX-001, PERF-003 *(no checkpoint; killed mid-loop, later users silently never refreshed)*, PROD-001, XPLAT-006 *(all web failures collapse to one generic card)*.

**Highest-leverage intervention:** land the OBS-001/002/003 telemetry substrate first (alerting channel + client crash reporting + structured logs, ~$0/mo, ~4 days), then adopt one review rule enforced in CLAUDE.md/code-review: *no swallowed error without a log line and counter* — and retrofit exactly the five known-silent hot spots (SyncEngine SKIPPED, SyncChangePublisher empty-registry return, `|| true` job updates, nutrition-day `.catch(()=>null)`, NutritionRepository double-`runCatching`). The substrate converts every future instance of this pattern from weeks-to-notice into minutes-to-notice.

### Pattern B — "Cross-layer contracts exist only as convention" — **ACCEPTED**

**Root cause:** one person (plus agents) hand-maintains every wire and semantic contract across 4 platforms — DTO mirrors ("keep in sync when DTOs change" comments), the collection-alias registry, duplicated business rules (med scheduling, composite rescale, unit constants, day-key semantics), backend layering rules in prose — with zero mechanical enforcement anywhere on the first-party surface. The tooling exists in-house and proves the point: the third-party /v1 API has byte-for-byte OpenAPI snapshots + an oasdiff CI gate, and it has never shipped a drift bug; the internal API has none and has shipped ≥3 (slash-collection alias, sync-doc parse vanish, entryId round-trip 400).

**Members (13):** ARCH-001, ARCH-002, ARCH-003, ARCH-009, TEST-005, DATA-008, OBS-005, XPLAT-001, XPLAT-002, XPLAT-003, XPLAT-004, XPLAT-005, XPLAT-008.

**Highest-leverage intervention:** apply the in-house /v1 pattern inward (ARCH-002's prompt): a springdoc snapshot group for `/api/me/**` + a checked-in emitted-collections fixture asserted byte-identical by a backend test and an Android `CollectionRegistry` test, plus shared JSON test-vectors for the two duplicated business rules (med due-ness, compositeTotal). ~3–4 days, and it converts the repo's single most recurrent shipped-bug class into a CI failure.

### Pattern C — "Infra knowledge lives outside the repo" — **ACCEPTED**

**Root cause:** Terraform/OpenTofu exists (251 LOC) but manages almost nothing and is never applied by automation; the real infrastructure is shell-script bootstrap + hand-run gcloud + operator memory. Result: declared-but-not-applied controls (idempotency TTL on the wrong DB), live-vs-repo drift (trigger SA: YAML says `tesseta-ci@`, live runs compute-default, the setup script contradicts both — re-running the "idempotent" script would break deploys), unmanaged critical state (no backups, no rules, no budget, no monitoring — none representable in the current IaC), env contracts that exist only as cloudbuild YAML comments, and runbooks (headless-gcloud-is-dead → ADC+REST) that exist only in one human's memory.

**Members (14):** DATA-001, DATA-002, DATA-005, OBS-001, COST-003/OBS-010, COST-005, CICD-006, CICD-009, DX-001 *(runbook half)*, DX-003, SOTA-010, SUP-007 *(no scheduled scanning)*, PERF non-finding *(manual index-deploy script)*, DX-011 *(AGENTS.md squatted — agent-facing knowledge misfiled)*.

**Highest-leverage intervention:** one "reconcile-then-manage" pass: import live state (Firestore DB settings, triggers+SA, budget, monitoring) into the existing tofu root, add `monitoring.tf`/`budget.tf`/backup schedule there, fix the TTL database target, and make terraform-ci run `tofu plan` against live with drift surfaced as a failing check. This single pass closes DATA-001/002/005, OBS-001, COST-003, and defuses CICD-006, and gives every future infra fact a home that agents can read.

### Pattern D — "The last mile is unowned" — **ACCEPTED (it is genuinely one pattern)**

**Root cause:** with no external users, "works in my flow" terminates effort; there is no definition-of-shipped that includes *verified in prod, wired to its trigger, linked from the UI, with the placeholder removed*. The result is a distinctive stratum of 90%-built artifacts: features shipped onto a dead push channel with UI copy promising notifications that never arrive; a comprehensive UAT harness and instrumented sync suite that run in no automation; ECDSA verification implemented but off; a docs-linter nothing runs; a jacoco "ratchet" comment with no rules; placeholder privacy URLs while the real pages already exist; LICENSE = "TBD"; version = `0.0.2-SNAPSHOT`; a hello-world wear app; an 8KL OAuth platform with zero consumers; a Withings button with no prod secrets; a permanently blank Readiness tile. This is distinct from Pattern A (error-path *style*) — it is a completion-discipline gap, and the fix is process, not code.

**Members (16):** PROD-001/UX-004, PROD-006, PROD-008, PROD-009, PROD-011, COMP-002/PROD-007, SUP-004, CICD-008, TEST-003, TEST-004/DX-009, TEST-009, SEC-007, DX-004, DX-010 *(two pre-analyzed S-effort wins unbanked)*, OBS-007 *(actuator on classpath, unexported)*, DATA-005 *(rules never written/deployed)*.

**Highest-leverage intervention:** a lightweight "shipped = verified" checklist in the PR template / CLAUDE.md (trigger wired? prod-verified end-to-end? placeholder removed? runs in CI or on a schedule?) plus one dedicated last-mile sweep week: fix FCM SHAs then E2E-verify each async flow, wire uat.sh + connectedAndroidTest + check-docs.mjs into scheduled CI, flip sig-verify, point About at the real URLs, mothball wear + the OAuth platform behind flags. Almost everything in this stratum is ≤1 day each.

### Pattern E (reconciler-added) — "Single-user assumptions are load-bearing while the front door is open" — **ACCEPTED**

**Root cause:** the entire risk calibration of the audit corpus — COMP's "trigger: user #2", TEST-001's isolation gap, SEC-002's cross-user-mutable catalog, PROD-002's missing first-run, DX-008's PHI-in-dev, COST-002's economics, PROD-012's founder hardcodes — treats "user #2" as a future, operator-chosen event. But SEC-001 proves the trigger condition is *already satisfiable by strangers*: `UserProvisioningFilter` auto-provisions **any Google account** on first request, with no allow-list, no rate limit, and a published privacy policy already making promises to whoever walks in. The deferrals are individually sound and collectively unsound: every "fine at n=1" verdict silently assumes a gate that does not exist.

**Members (12):** SEC-001, SEC-002, TEST-001, PROD-002, COMP-001, COMP-002, COMP-004, COMP-005, COMP-006, DX-008, PROD-012, UX-011.

**Highest-leverage intervention:** a ~2-hour change: gate provisioning behind an allow-list env var (`app.signup.allowed-emails`, fail-closed like `ADMIN_EMAILS`) until the user-#2 checklist (deletion, consent surface, isolation tests, rate limits) ships. This one control converts a dozen "high at user #2" findings back into genuinely deferred items and makes the trigger operator-owned again — the highest severity-reduction-per-line-of-code available in the entire audit.

**Candidate (f) "graceful degradation masks outages" — folded into Pattern A** (the safety-net-masking members are listed there); not distinct enough to stand alone.
