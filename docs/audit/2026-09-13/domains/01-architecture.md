# D1 — Architecture & Design Audit (ARCH)

Date: 2026-09-13. Auditor: D1. Scope: module boundaries, layering, coupling, domain-model coherence, state ownership, concurrency/consistency model, docs drift, Chesterton's fences.

## BLUF

The architecture is in unusually good shape for a solo-founder monorepo: the backend's convention-only package layering (`api → core, integrations; persistence → core`) shows **zero violations today** — greps for every forbidden import direction (core→api, core→persistence, core→integrations, api→persistence, persistence→api, integrations→api, Spring Web in core) all came back empty [Certain] — and the Android Gradle module graph is clean (no feature→feature edges, wear depends only on `:core-domain`, exactly as the docs claim) [Certain]. The real architectural risk is not layering but the **hand-maintained wire contract**: every domain concept exists as 4–6 parallel model definitions (backend record, backend response DTO, web TS type, Android domain class, Android sync-doc shape, Room row) with no contract test or codegen, and this exact gap has already produced two shipped data-loss-class bugs (the sync slash-collection alias and the nutrition sync-doc parse failure, both memorialized in code comments) [Certain]. Secondary concerns: the backend layering has no automated enforcement so its current cleanliness is one unreviewed agent PR away from erosion; churn hotspots are concentrated in god files (WorkoutSessionScreen.kt 2,721 lines; NutritionController.java 1,248 lines); and backend/CLAUDE.md's package inventory omits the sizable `platform` subsystem and the `uat` package. The codebase is dense with explanatory comments encoding hard-won production lessons — a Do-NOT-change list is included below and should gate any refactoring agent.

### ARCH-004 — Ownership of "today" is split three ways, and the server's timezone fallback silently reverts to UTC
- **severity:** low
- **confidence:** [Certain] on mechanics; [Likely] on user impact
- **evidence:** Server derives the user-local day from the `X-Timezone` header (`backend/.../api/support/RequestTimeZone.java:22`, header attached by `android/.../data/net/TimeZoneInterceptor.kt` and `web/lib/api.ts` + `web/components/TimezoneCookie.tsx` [Certain]); fallback at `RequestTimeZone.java:30-33` is `ZoneId.systemDefault()` — "UTC in production" per its own javadoc, which the doc frames as "callers that don't yet send the header are unaffected" i.e. affected-but-status-quo [Certain]. Meanwhile Android mints day keys client-side in ~20 non-test sites (`grep 'LocalDate.now()'`: `NutritionTodayViewModel.kt:58`, `DrinkSessionViewModel.kt:149`, `MedicationRepository.kt:240/265/294`, `FirstSyncGate.kt:127`, …) [Certain]. - **impact:** Coherent by design for the write path (offline-first requires client-minted days), but there are two soft spots: (a) any future caller that omits the header gets UTC days with no warning — an evening US-timezone workout dates to "tomorrow" (the exact bug `RequestTimeZone`'s javadoc says it was built to kill); (b) around midnight or travel, a device-minted day and a server-derived day for the same event can differ, and nothing reconciles or even logs the disagreement.
- **effort_days:** 0.5
- **autonomy:** agent-unattended
- **null_option_cost:** Near zero while both first-party clients reliably send the header; becomes real when third-party `/v1` platform clients (ADR-0020) or new jobs call today-style endpoints without it.
- **prompt:** "In `backend/src/main/java/com/gte619n/healthfitness/api/support/RequestTimeZone.java`, the fallback when `X-Timezone` is missing/invalid is `ZoneId.systemDefault()` (UTC in prod). Also grep the backend for `LocalDate.now()` with no ZoneId argument outside tests and list (do not change) any hits in today-semantics endpoints as a review comment in the PR description. ## Do NOT change (Chesterton's fences)

All verified by reading the cited code this run [Certain]:

1. **`ConflictResolver` server-clock invariant and equal-timestamp tiebreak** (`android/core-data/.../sync/ConflictResolver.kt:12-28`) — "keyed on the **server** clock, never the device clock (invariant 3)"; equal ts → incoming server doc wins for idempotent re-application. Changing either silently breaks offline reconciliation and re-introduces echo-loop bugs.
2. **Successor-chain refresh recovery with deliberately NO grace-period knob** (`backend/src/main/resources/application.yml:80-84`; `auth/AppSessionProperties.java:19-21`; ADR-0019) — a lost-response refresh replay is recovered by chain-walk, "however long the phone was offline. No grace-period knob to tune." This replaced the family-burn forced-logout bug; do not "add a grace window for safety."
3. **Lazy injection in `SignOutSideEffects`** (`android/app/.../auth/SignOutSideEffects.kt:48-50`) — "Deferring construction to first use (sign-out time) breaks that Hilt dependency cycle" and avoids building the network stack at registration. Eager-izing it re-creates the cycle.
4. **`CollectionRegistry` alias rows — especially the slash forms — and its skip-unknown-don't-crash policy** (`android/core-data/.../sync/CollectionRegistry.kt:22-25, 40-66`) — each slash alias memorializes a shipped cross-device data-loss bug ("a dose taken on another device never reached this mirror"); unknown collections returning null is deliberate forward-compat with newer backends.
5. **Terminal-4xx parking in the outbox** (`OutboxRepository.kt:27-33, 61-70`) — parked rows keep their payload ("no silent data loss") and are excluded from automatic drains ("rather than re-sending a doomed payload forever"). Both halves matter; don't convert parks to drops or to auto-retries.
6. **`NutritionEntrySyncDoc` dual-shape parsing** (`NutritionRepository.kt:87-112`) — the second shape exists because sync-written rows otherwise failed to parse and "the entry vanished from the day". Consolidate around it if desired (ARCH-003) but never delete a shape without migrating persisted rows.
7. **Fail-closed empty defaults for privileged config** (`application.yml:86-90` admin emails — "a missing/misconfigured env can never silently grant admin to a baked-in personal address"; same pattern at `:105` PLATFORM_RSA_KEY and `:238`). Do not add "sensible" fallback values.
8. **No `collectionGroup` queries in the sync delta reader** (`FirestoreSyncChangeReader.java:46, 115, 187` — "so it never reads another user's documents") — accepted N+1 read cost is the price of structural tenant isolation; a PHI-relevant invariant.
9. **`UatStubConfig` living in main sources with double gating** (`backend/.../uat/UatStubConfig.java:29-34`) — `@ConditionalOnProperty` master switch + per-bean `@ConditionalOnMissingBean` so it "can never shadow the real client or the unit-test fakes"; it must stay on the runtime classpath for `infra/scripts/uat.sh`.
10. **The single-module backend collapse itself** (`backend/CLAUDE.md` Layering) — the 5-module split was removed deliberately ("that ceremony wasn't worth it"); the correct enforcement response is a test (ARCH-001), not re-modularization.
11. **`X-Timezone` server-side day derivation** (`api/support/RequestTimeZone.java`) — exists to stop UTC-server "evening workout dated tomorrow" bugs; don't replace with server-clock `LocalDate.now()` anywhere.
